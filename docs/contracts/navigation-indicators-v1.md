# Navigation indicator contract v1

Owner-approved presentation: the revised Maps camera pill, `provider-data-design80/camera-fresh.png`. Its size, typography, icon scale, right-column progress and alignment are fixed. Maps and Vela consume the same visual vocabulary and the same 19 unchanged owner-supplied assets. Provider data determines the contents; an asset does not establish provider support.

The owner approved the complete Vela layout on 7 November 2026 after reviewing run92: current 100km/h, maximum 130km/h and the camera 300m pill together in native Drive mode. Maps and Vela presentation is fixed. The design inputs were artificial; this does **not** claim natural event delivery, speech or all 19 families accepted. Continue the remaining focused functional gates using the approved presentation.

## Envelope, identity and authority

Keep `WARNINGS_V1` / `protocol_version=1`. New optional primitive fields are additive. Producers annotate non-CLEAR events with `indicator_contract_version=1` and `indicator_kind` from the table below. Receivers classify the original native fields, rather than trusting arbitrary text or an icon filename.

- Preserve `provider_session`, `warning_id`, monotonically ordered `sequence`, `revision`, original `native_type`, `native_subtype`, category, priority, phase, language and source text. The normalized visual family does not replace native identity.
- `UPSERT` supplies display state. `ANNOUNCE` additionally represents an actual captured native announcement decision. A visual-only road/country transition never acquires announcement authority. A settings sound preview is not a driving warning.
- Use source elapsed-realtime milliseconds, on the same Android device. Drawing, replaying a snapshot or deriving receiver geometry must not advance the source observation clock, expiry or announcement index.
- `CLEAR` removes the matching identity; session replacement invalidates the old session. Provider removal, native stop and zone exit remain authoritative. No persistent card may survive `state_until_elapsed_ms`. The maximum state window is 30 seconds; new road/country/overspeed notices use 10 seconds.
- Preserve the existing receiver category and Voice/Tone/Silent choices, native speech deadlines, repeat/preemption and route relevance. Indicator normalization does not change audio grants or native eligibility.
- Unknown/native types retain useful native text with the incident glyph. Do not infer semantics from translated text. Social, parking and personal-route exclusions remain excluded.

## Geometry and units

All distances are integer metres, canonical speed values km/h, coordinates WGS84 latitude/longitude, relative bearing degrees in `[0,360)`. Display-unit conversion is receiver-only. FM's final road-limit cache is already metric, including when its country setting is the UK; never convert it from mph a second time.

| Field group | Required metadata and meaning | Receiver behaviour |
|---|---|---|
| `distance_m` | `distance_observed_elapsed_ms`, `distance_estimated` | Use only while state is valid and observation age <=5s. Explicit valid native0m is allowed; a missing field must not default to0. |
| `trigger_m` | `trigger_observed_elapsed_ms`, `trigger_estimated` | Native announcement/approach threshold. Positive and fresh only; never synthesize it from icon type. |
| `range_m` | `range_observed_elapsed_ms`, `range_estimated`, `range_origin` | FM's `native_ui_max_distance` is a native visual span, **not** an audio trigger. Positive/fresh range permits a visual approach bar when trigger is absent. |
| `latitude`, `longitude` | Both required, `position_observed_elapsed_ms`, `position_estimated`, source clock origin | Missing/partial/default parser coordinates are not targets. Static native point targets can remain fixed until state expires; moving targets cannot acquire fresh coordinates by redraw. |
| `relationship` / `relative_bearing_degrees` | Direction is unknown unless qualified; a normalized direction carries `relationship_observed_elapsed_ms`, `relationship_estimated`, `relationship_origin`. | Direction expires independently after5s. Heading alone, vehicle icon or emergency category cannot imply Behind/approaching. |

`WarningGeometry` is a display-only value. It does not rewrite the immutable source event or renew speech. For fixed point targets, prefer fresh native distance. Otherwise use the receiving app's guarded directed route with a fresh accurate fix; during active navigation withhold the estimate if the route is unavailable/ambiguous. While browsing, allow only a conservative forward-bearing estimate within2km. Mark receiver-derived distance estimated. Existing passed/off-route filtering applies to the visuals as well as speech.

For FM15 early warning geometry, bind downloader `setPostData`/`setPostLocation` request Location to its typed `onPostExecute(JSONObject)`, then the exact same JSONObject's parser result. Native manager callbacks can contain a newer last Location than the request, so callback read time/latest GPS must not substitute for measurement time. Require actual JSON distance/max_distance/heading/type presence and consistency with the returned model (including the native report's25m rounding). Retain the request fix's elapsed clock. Partial parser results retain raw diagnostics but gain no fabricated canonical geometry. Missing response coordinates cannot become `(0,0)`.

FM responder relative position is derived from explicit response coordinates and the correlated request fix/bearing, with accuracy, distance-consistency and minimum-separation checks. Rear sector135–225 degrees permits Behind; front sector within45 degrees permits ahead; other positions stay unknown. This establishes relative position, **not** closing speed, future route, lane or proof that the responder is moving towards the user. Keep native incoming/stationary/motion facts separate.

Keep independent facts independent: a native `max_distance=0` supplies no visual span but does not invalidate a separately verified distance. FM's actual request uses `Location.getBearing()` and `getSpeed()` without requiring Android presence flags. Those flags are therefore not extra eligibility for displaying its native distance. A relative-position label still requires an actual finite own bearing and a valid bearing-accuracy value when supplied; missing/invalid direction does not erase the verified distance.

The numeric request getters must still be finite: FM's JSONObject serialization rejects NaN/infinity. Such a failed request cannot be associated with a response from earlier task data. Invalid bearing **accuracy** only withholds direction; it is not a serialized request field and does not invalidate an otherwise verified distance.

Retain parser presence separately from successful canonical geometry. A native JSONException can return a partially populated model; clear its default/partial target before considering request geometry. A complete fixed crossing retains its fixed-target qualification only when its JSON coordinates and correlated model are verified. Unrelated legacy/CITS models are not reclassified as partial network responses.

Vela's original `cw.u()` prefers the stable callback rectangle (`u0`) over the current visible rectangle (`K`). The overlay layers use current visible bounds first, clipped in surface coordinates, and use stable bounds only when the visible callback is unknown. An explicitly empty visible area withholds the overlays. Run89 proved that both callbacks can still include map-action buttons: on a 1190px surface their right edge was 1154 while the zoom button began at 1114. Both the normal combined speed badge and warning pills therefore also reserve an 80dp end column, retaining that anchor while controls auto-hide. A narrower host reservation still wins. The native fields are guarded at patch time; pill styling is unchanged. ## Average-zone lifecycle

- APPROACHING distance means distance to the zone. WITHIN distance means remaining in the zone. A correlated Waze segment overrides the display DTO only when correlation, phase, native zone state and clock agree; original native distance and audio decision remain intact.
- While within a correlated average segment, never fall back to an old entry-point0m when remaining geometry expires. Never divide remaining distance by an approach/announcement threshold to invent zone progress. Use fresh native zone percent, or withhold the bar.
- A receiver-derived route/heading distance to the entry point is also forbidden after the source says WITHIN/InZone/LeftZone. Point-passage filtering cannot retire that visual zone merely because its entry camera is behind the car. These display rules do not rewrite the original event's category, relevance or speech authority.
- Native zone-percent clocks come from the genuine repository observation. A later sound/controller callback cannot refresh that clock.
- Native segment facts have their own observation clock. Preserve correlated facts across ordinary descriptor/repository/sound reads for the same native identity/type without renewing that clock; only genuine segment removal, alerter removal or session stop retires the correlation. Known InZone/LeftZone state alone is enough to withhold an unqualified entry-point distance when correlation is temporarily unavailable.
- The separate telemetry path owns numeric average, partial-average qualification, limit, progress, remaining distance and enter/exit. A native “average too high” decision supplies an alarm, not a measured numeric average. Preserve its warning even when an average panel is already visible.
- Entry, active updates, native exit/removal, session stop and expiry clear the relevant warning/panel using their existing identities. Do not infer a full completed average from a camera position or reset the source zone just to redraw.

## Product implementation and verification boundary

Shared consumers: `IndicatorContract`, `WarningEvent`, `WarningGeometry`, `CarWarningPills`, `WarningView`; Maps `CompactSpeedView`/`MapsGuidanceCoordinator`; Vela `CarUi`/`TelemetryRuntime`. Assets and their byte hashes are in `patches/src/main/resources/navigation-warning-icons/catalog.json`.

FM15 additional roots and full operand/catch guards: `patches/.../flitsmeister/NativeIndicatorData15.kt`. Existing accepted-warning hooks remain the publication authority. New parser bookkeeping only supplies facts. Road overspeed is hooked at the actual `erb.a` sound call, average overspeed at `zl.invokeSuspend`, average clear at `xl.e`, and country state around the GPS-only `b65.y` root. `SignalScreens.playSound` and other settings previews are excluded. FM `NavigationBroadcasts.road` supplies final metric road-limit data. Waze's original descriptor/segment DTOs remain pinned by its existing patch guards.

Native register lifetimes matter after R8: `erb.a(Location)` reuses p1 for the fci engine by its sound call. Capture that decision through p0, the original controller, and read its native Location field c. Never pass the late p1 register as Location.
