# Gboard 18.8.0.1022711984-beta: function-level notes for the patched surfaces

Date: 2026-11-22. Every signature below was read from the 18.8.0-beta dex (jadx tree +
`dexlib2` dumps), not inferred from 18.6.3. `regs`, instruction indices and field names are
what the stock build actually contains, so a patch can assert them.

## 1. InputMethodService lifecycle (`afae` = GoogleInputMethodService)

`afae` extends `android.inputmethodservice.InputMethodService`; `ihw` extends `afae`;
`com.android.inputmethod.latin.LatinIME` extends `ihw`.

`afae;->onCreate()V` — `regs=12`, `p0=v11`, 3 try blocks, one `return-void`.
Sequence: Trace → previous-instance teardown → `H()` → `super.onCreate()` → window setup →
`afae;->al:Lafaf;` nav-bar handling → field writes → `return-void`.
`v11` (this) is clobbered at index 172 (`move-result-object v11` after `getWindow()`), so any
hook that needs `this` at the end must save it into a register that is dead **after** the last
use of that register before the clobber. In 18.8 `v9` is used by `new-array v2, v9` (index 166)
and by `invoke-direct {2,9,4}` (index 190, *after* the clobber), so `v9` is unusable; `v10` is
dead from index 168 to the end and is what the Web Clipboard patch now saves into.

`afae;->onStartInputView(EditorInfo;Z)V`, `onStartInput`, `onFinishInput(View)`,
`onWindowHidden()`, `onDestroy()` — the lifecycle points used by Calculator, Incognito,
Toolbar Editing Buttons and Web Clipboard. All are `PUBLIC|FINAL` with a single return, which
is what `applyVoidExitLifecycleDelegate` requires.

## 2. Flag getter (`Ladfs;` / `Ladgf;`)

- `Ladfs;->g()Ljava/lang/Object;` — `regs=3`, `p0` = receiver (`v2`), one `RETURN_OBJECT`.
  It materialises the value from `Ladgf;->a:Ljava/lang/Object;` and exposes the flag name in
  `Ladfs;->a:Ljava/lang/String;`. `Ladfs;->f:Ladgf;` is the current snapshot (value +
  `b:I` priority).
- Every flag in the build is a static `adfh` field created by `adfk.a/e/c/b/i(...)`; the
  getter above is shared, which is why one hook can force any flag by name.

## 3. Soft-key bind (`SoftKeyView;->s(SoftKeyDef;J)Z`)

`regs=8`, 2 try blocks, one `RETURN`, `PUBLIC|FINAL`. Writes `SoftKeyView;->f:J` (the bound
token), `e:SoftKeyDef`, and reads `SoftKeyDef;->e/f/m`. This is the single bind path used by
the spacebar logo, top-row swipe, long-press actions and Latin-globe patches.

## 4. Access points (`Laadr;` / `Laadm;` / `Laaej;` / `Laajh;`)

18.8 split the descriptor API:

| Member | What it does |
|---|---|
| `Laadr;->m()Laadm;` | static factory; allocates `Laaej`, calls `q("")`, `l(0)`, `m(0)`, `k(0)`, `j(0)`, `f(0)`, seeds the action maps |
| `Laadm;->v(Ljava/lang/Runnable;)V` | adds the default click action (old `q(Runnable)`) |
| `Laadm;->h(ActionDef;)V` | adds a fully-specified action |
| `Laadm;->w()V` / `t()V` / `e(String,Object)` | copy-on-write, expand-icon, generic param |
| `Laaej;->q(String)V` | descriptor token (string id) |
| `Laaej;->l(I)V` | icon resource; writes private field `r` (old `i(int)`) |
| `Laaej;->a()Laadr;` / `Laadm;->b()Laadr;` | build the `AccessPoint` |
| `Laaej;->d:Ljava/lang/String;` | title/label |
| `Laajh;->g(Laadr;Z)V` | registers the descriptor with the access-point controller |
| `Lauco;->n(Ljava/util/Collection;)Lauco;` | immutable-set copy used when extending the order catalog |
| `Laajh;->g:Laaia;` | order helper; `Laaia;->b:Lauco;` master catalog |

The extension's reflective `Handles` now resolves factory `aadr.m`, token `aaej.q`,
icon `aaej.l`, action `aadm.v`, build `aaej.a`, register `aajh.g`, title field `aaej.d`.

## 5. OCR module request (`lbaki`, `Lbakh;`, `Lxws;`, `Lzdv;`)

`Lbaki;->a(Lbaje;)[Lxli;` — static; builds the MLKit module spec array for a config.
`Lbakh;->a()[Lxli;` — instance, implements `Lxns;` (the `a()[Lxli;` provider the module
manager asks). `Lxws;->a([Lxns;)Lzdv;` enqueues the request and returns a task (`Lzdv;`).
The 18.6.3 "request object" (`Lytk;` there, `Lytk;` in 18.8 is now a protobuf) no longer
exists; the patch therefore overrides the *provider* (`Lbakh`) rather than a request call,
and casts the delegate result to `[Lxli;`.

## 6. Voice-correction store (`akof`, `MUSE_STATS`)

`Lakof;` (interface `Lagvl;`) exposes:

| Member | Meaning |
|---|---|
| `d(Laknd;Ljava/lang/Class;)Lbapd;` | read the feature payload |
| `p(Laknd;)[B` | raw bytes |
| `n(Laknd;Ljava/lang/Class;Latri;)V` | update through a transformer |
| `t(...)` (same shape) | second update variant |

18.6.3 passed an `AddWords(Object,int)` *value* as the third argument. 18.8 passes a
transformer implementing `Latri;->apply(Object)Object`. There are four `MUSE_STATS` writers in
the build:

| Class | Ctor | Purpose |
|---|---|---|
| `Lkbi;` | `(String word, List phrases, int max)` | single-word add, tags the entry `USER_ADDED` |
| `Lkbd;` | `(Set)` | set-based (import/delete) |
| `Lkbm;` | `(Set)` | set-based |
| `Lakhr;` | `(auaz, Instant, int, int)` | `DeviceContextMuseStatsUpdater` (dcontext) |

`Lkbi;` is a *top-level* synthetic class with no back-reference to the fragment, so it can be
instantiated off-device-UI: `new kbi(word, emptyList(), maxCount).apply(stats)` yields the
updated `akjx` (MuseStats). The Rambler contact patch therefore builds one per name behind a
`java.lang.reflect.Proxy` for `atri` (extension `appendWords`), and Gboard's own protobuf code
does the encoding.

## 7. Parakeet / recogniser contract

Recogniser interface `Lwke;` (extends `Lakrt;`): `a()Lwkd;`, `h()V`, `j(Laksu;)V`, `k()V`,
`o([BLwkr;Lwil;Lwkc;)V` (retry), `p(Lwkr;Lwil;Lwkc;)V` (start). The last parameter of
start/retry is the callback: `Lwkc;`.

`Lwkc;` has 11 abstract methods (18.6.3 had fewer): `a` onListening, `b(Wkb)` onRecognitionError,
`c` onRecognitionPaused, `d` onRecognizing, `e(int)` onSpeechLevelUpdate, `f` onStartFailure,
`g` onStartSuccess, `h` onStopListening, `i(Laksu)` onStopListening(reason), `j` onStopRecognition,
`k(Lbbhl)` **onTranscriptionUpdate**.

Results therefore arrive as a protobuf, not a `List<Hypothesis>`:
`Lbbhl;` (extends `Lbanv;`) holds repeated `Lbbht;` hypotheses. Both messages use the generated
base builder API: `Lbanv;->n()Lbanp;` (newBuilder), `Lbanp;->w()V` (ensure mutable),
`Lbanp;->b:Lbanv;` (message under construction), `Lbanp;->t()Lbapd;` (build).
`Lbbht;` carries `b:I` presence bits (1 = text `c:String`, 2 = final `d:Z`), and
`Lbbhk;->b(Lbbht;)V` appends a hypothesis to the transcript.

Gboard's own template for this is `krv.e(krg)` (JetsonLiteRecognizer, log "handleResult"): it
builds one `bbht` (text, final, confidence 1.0), wraps it in `bbhl` and calls
`wkc.k(...)` then `wkc.j()`. `krv.m()`/`krv.n(akrs)` delegate to the Lite engine instance
(`krv;->m`), so the patch cannot copy those two inherited bodies into a generated class; they
are emitted as default-value stubs (programmatic `const/4` + `return-object`, because morphe's
inline smali compiler wraps fragments in a *void* synthetic method and cannot parse
`return-object` bodies).

## 8. Theme contract (`vkw`/`vmb`/`vku`/`ajgb`/`vmj`)

`ThemeListingFragment` → peer `Lvmb;` (field `a`), peer context `b`, launcher `t:Lvku;`,
peer result `j(Landroid/content/Intent;)V`, launcher `Lvku;->b(Intent,I,Bundle)V`.
The grid "+" handler is `Lvmj;->c(Lvmh;Lvmn;I)V`; it takes the *interfaces* the peer and the
adapter implement, while all field access stays on the concrete peer `Lvmb;`. The theme ZIP
validator is `Lajgb;->h(Ljava/io/File;)Z` (logger `theme/inflater/ZipThemePackage`), and the
fragment's activity-result handler is `ThemeListingFragment;->X(IILandroid/content/Intent;)V`.

## 9. Free cursor / floating keyboard (new beta behaviour)

`admk` holds `free_cursor_*`; the only consumer is `adoe`. `afvg.o`
(`enable_invisible_floating_resizing`) is read in `afnh.activate` (enables the resize mode) and
in `afri` hit-testing, where it adds the invisible edge band for floating layouts whose
`ad()==3`. `acyl.b` (`enable_emoji2`) selects the emoji provider class in `acsv`
(`acxr.a` vs `acxo.a`). `DragConfirmationPopupView.a` (`enable_remove_suggestion_v2`) switches
the drag-to-remove confirmation layout at three call sites.

## 10. Rambler emoji matching

`knv` holds the tuning flags; `knx` builds `swa` (the `EmojiEmbeddingSearcher`,
`libs/search/emoji/search/EmojiEmbeddingSearcher`) with `kta.EMOJI_MATCH_*_LATENCY`
(`VoiceInput.Jetson.Emoji.*`); `knw` is the matcher; `kny` compiles the marker
`\[EMOJI:([^\[\]]*)\]`, i.e. dictation output may emit `[EMOJI:description]` and the matcher
resolves it through the embedding index. `kov` reads `aasf.R`
(`jetson_position_cursor_after_last_diff`) to place the cursor after the last diff and
`aasf.C` (`send_emoji_persona_to_s3`) in a ternary whose **both** branches are
`Optional.empty()` — the persona upload is scaffolded but sends nothing in this build.

## 11. Rambler request pipeline (`kov` = AgenticDictationExtension)

`kov` is `com/google/android/apps/inputmethod/libs/agenticdictation/extension/AgenticDictationExtension`,
constructed as `(Context, agrh, agrd, kwy, kny)` — the last two are the emoji-match matcher
wrapper (`kny` holds the `knw` matcher) and its provider.

| Member | Behaviour |
| --- | --- |
| `A(kuh, kvc, knj, wkq)V` | Opens a recognition session: stamps `Instant.now()`, stores the request object in `g`, appends the attempt to a `CopyOnWriteArrayList`, then drives the session builder (`j()`, `d.e(...)`, `v()`, `n()`, and `u()` for the `kvc.f` state). When the attempt is not the first (`knj != knj.c`) it emits `ksp.USER_RETRY` with the retry count. |
| `G(aepw, aesl, bbht)kox` | Builds the request payload: takes the current text state (`aesl`: text, selection, selected text via `o()`), the editor/app info (`aepw`) and a finished hypothesis (`bbht`), and produces `kox`. This is where the surrounding-text window, cursor-awareness (following paragraphs when `jetson_enable_cursor_awareness`), app context (`<app_context>`) and the custom-instruction guard (`<user_instruction>` wrapped in the fixed anti-jailbreak prompt) are assembled. |
| `ea(bbhl)V`, `i(bbhl, akrw)V` | Consume the transcription proto delivered by `RecognizerCallback.onTranscriptionUpdate` — the same `bbhl` type the Parakeet fallback emits. |
| `k(EditorInfo, Z)V` | Input-view start: captures the field/app for the next request. |
| `m(adan)Z`, `n(aeuj, EditorInfo, Z, Map, adbd)Z`, `E(kuf, Z)Z` | Acceptance and eligibility gates (field/app allow-lists, quota, activation type). |
| `O(Z)[B` | Returns the cached PCM buffer used for a retry. |
| `C()/D()Z` | Session state predicates used by the extension's public entry points. |
| `dY()/e()/gg()/eb(Duration)` | Lifecycle and timing hooks (extension start, session end, duration reporting). |

The flags read inside the pipeline are the `aasf`/`knv` families; our patch set forces
`enable_agentic_dictation`, the toolbar flags, `ad_activation_type=2`, the dictionary/context
flags and now `jetson_position_cursor_after_last_diff` (two cursor-placement sites in `kov`).

## 12. Clipboard store (`ljp` = ClipboardDataHandler)

`ljp` is `com/google/android/apps/inputmethod/libs/clipboard/ClipboardDataHandler`, constructed
with `(agrh)`; it holds the `Context` (`b`), the system `ClipboardManager` (`c`), an executor
(`z`), the change notifier (`v:agvi`), the loaded item set (`w`) and a sync flag (`x`).

| Member | Behaviour |
| --- | --- |
| `onPrimaryClipChanged()V` | The system callback. Returns immediately when `afcu.f()` is true (Incognito), otherwise calls `g()`. This is the call site the Incognito patch hooks. |
| `g()V` | Submits a callable that reads `getPrimaryClip()` + `getPrimaryClipDescription()`, notifies observers through `NotificationCenter` (`abbv`), then persists the clip via `b(context, clip, description, true)`. |
| `b(Context, ClipData, ClipDescription, Z)` | Row insert/update: dedupe, retention pruning, sensitive-content marking, timestamp and column-count metadata. |
| `i(String uri)V` | Deletes image files that are no longer referenced by the clip database (`deleteImageFileIfNotInDatabase`). |
| `n()V` | Clears the current clip: empties the text, cancels the pending callable, removes the row. |
| `o(long)V` | Writes `clipboard_primary_timestamp` through `ahws.H(context, null).h(...)`. |
| `e()Ljava/lang/String;` | Current clip text used by the keyboard's paste affordances. |
| `p(adfh)V` | Reacts to a changed flag: enables/disables the notifier (`agvi.c(abok.a)` vs `d()`). |
| `B(Cursor)V`, `A(Uri, int)Cursor`, `q(Uri)V`, `h()V` | Row mapping and content-provider queries (`lip.d(context, 2, -1)`). |
| `x()/y()Z`, `v(Z)V`, `r()/s()/t()/u()/w()` | Sync/availability predicates and lifecycle helpers. |

Our Clipboard Enhancements patches land here: retention and prune
(`GboardClipboardPrunePatch`), loader hook, adapter trim/bind and the column-count delegate
(`ClipboardKeyboard;->b()I`), plus the two 18.8 beta chip flags which are read in `shc`/`lgj`,
one level above this handler.

### Intent table and dispatch

`batv` is the writing intent enum: `INTENT_UNDEFINED(0)`, `TARGETED_EDITING(1)`,
`AUTO_FIX(2)`, `LINKIFY(3)`, `STYLE_TRANSFER(4)`, `COMPOSING(5)`,
`UNRELATED_TO_WRITING(6)`, `TRANSLATION(7)`, `CONTINUATION(8)`, `HIGH_LEVEL_EDITING(9)`,
`SUMMARIZATION(10)`. This is the "V2 intent table" our AI Writing Tools patch used to extend with
`INTENT_AUTO_FIX` on 18.6.3; in 18.8 the table is built in `ohu`'s constructor from an immutable
set (`auau` builder → `this.f`).

| Member | Behaviour |
| --- | --- |
| `ohu.a(oig)ogs` | Decision entry. If the intent is not style-transfer / not in the table / not targeted-editing it falls through to `b(oig)`; otherwise it checks the rewrite type (`batt.REWRITE_TYPE_UNSUPPORTED`) and returns a COMMAND_AMBIGUITY verdict |
| `ohu.b(oig)ogs` | Score-threshold arbitration: `oig.a() > this.e` plus regex match/mismatch and the two per-intent booleans decide `…_REGEX_MISMATCH_SUPRA_THRESHOLD` / `…_REGEX_MATCH_SUB_THRESHOLD` / `…_NOT_COMMAND` |
| `ohu.c(batv)` | style transfer allowed (`this.c && INTENT_STYLE_TRANSFER`) |
| `ohu.d(batv)` | targeted editing allowed (`this.b && INTENT_TARGETED_EDITING`) |
| `ohu.e(batv)` | intent present in the route set `this.f` |
| `ohm.c(oig, oku, ogs)` | `SmartEdit.handleIntent`: logs classifier metrics (`rpl.c`), resolves ambiguity through `ohu`, builds `ohv(oku, oig, ogs)`; when the result is not unambiguous and not a command it logs "SmartEdit intent classifier: CONTINUATION [SDG]" and dispatches the voice command through `NgaInputManager` (which rejects intents 0/8 and logs "Unsupported voice command intent") |
| `ohk` | `avva` callback capturing `(ohm, Instant, batv, oig)`; `a(Throwable)` failure path, `b(Object)` success path |
| `ohm.a(String)/b(String)` | model text helpers (classifier input/normalisation); `d()/e(Z)` start/stop |

The `SmartEdit` class imports `Interpreter`, `MobileBertIntentClassifier` and `NgaInputManager`,
which is the concrete classifier → route → assistant chain.

## 14. Gesture decoder (HmmGestureDecoder, ovs)

`HmmGestureDecoder` (`libs/hmmgesture/HmmGestureDecoder`) is the JNI face of the HMM gesture
recogniser (native counterparts: `nativeCreate(long, long, String, String)`,
`nativeDecode(long, byte[])`, `nativeGetFilteredResults(long, String[])`,
`nativeReset(long)`, `nativeSetKeyboardLayout(long, int, byte[])`, `nativeRelease(long)`;
`JniUtil.a` is the loaded-flag and `initJNI()` the loader).

| Member | Behaviour |
| --- | --- |
| `<init>(long handle, agrh metrics)` | wraps the native pointer in `abcn` (an `AutoCloseable` handle whose `a()` returns the long) |
| `a()V` | `nativeReset` when JNI is available |
| `b(int layoutId, axvu layout)` | `nativeSetKeyboardLayout(handle, layoutId, layout.j())` — pushes the key geometry the decoder needs |
| `close()` | releases the handle |

The decode call site is `ovs` (a motion-event handler): for gesture input actions
`-10028`/`-10029`/`-10044` it takes the first event's motion payload
`((ayka) adanVar.b[0].f).j()` (the trajectory bytes), calls
`HmmGestureDecoder.nativeDecode(handle, bytes)`, times it with
`oto.DECODE_HMM_GESTURE`, then branches on `otu` (a/b = gesture vs writing) to continue the
gesture or hand the stroke to the writing path; `ovs.h(adan)` is the predicate that accepts the
event, and `ovs.g(HmmGestureDecoder, axvu)` the layout hook.

The `SoftKeyView;->s(SoftKeyDef;J)Z` bind (see §3) is the other half of the touch pipeline: the
key view resolves a `SoftKeyDef` into a bound key, and the HMM decoder consumes the resulting
motion traces. Our gesture-family patches (long-press quick actions, top-row swipe, globe drag)
hook the pointer-owner and bind stages above this decoder.
